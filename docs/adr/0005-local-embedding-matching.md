# Chat is matched with a small local embedding model, with word overlap as the floor

Choice points and influence windows score each chat message against options by meaning, using `BAAI/bge-small-en-v1.5` through fastembed (ONNX on the CPU, about 67 MB, no PyTorch). We chose CPU embeddings over asking the AI backend to judge messages because scoring happens for every message in real time: a CLI call takes seconds and an Ollama model would compete with ComfyUI for the GPU, while an embedding takes milliseconds and costs nothing. The model is not bundled; the user downloads it once from Settings, and until then (or if it fails to load) matching falls back to word overlap. Even with the model loaded, each score is the higher of the semantic score and the word-overlap score, so exact wording and option numbers ("2") always count. Raw cosine similarity is rescaled from 0.50–0.85 to 0–1; those bounds are a starting guess, not tuned against real chat, which is why the Debug view exposes the match threshold as a live slider.
