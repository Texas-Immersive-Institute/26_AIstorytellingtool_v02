# AI runs through the Claude CLI, Codex CLI or Ollama, chosen in settings

The AI client in `packages/core` talks to one of three interchangeable backends: the Claude CLI, the Codex CLI (both run as subprocesses on existing subscriptions) or a local model through Ollama. The default is a setting, not code. We are deliberately not starting with hosted API keys: the goal is no extra per-call cost. The trade-off is latency (CLI calls take seconds) and GPU contention (Ollama shares the GPU with ComfyUI), so live features must tolerate slow replies and the debug view shows call timings. A hosted-API backend can be added later behind the same interface.

Matching audience messages to choice-point options and ranking them for influence windows does not use the chosen backend at all: it uses a small local embedding model on the CPU, so it is free, fast, and works with any backend (or none). See ADR-0005.

**Amended 2026-11-11 (milestone 5).** The default setting is `auto`: a playthrough uses the first backend that is ready, in the order Ollama, Claude CLI, Codex CLI, so a running local model is always preferred over spending a subscription. "Ready" means signed in, not just installed (`claude auth status`, `codex login status`): an installed but signed-out CLI fails every call. The CLIs run with tools disabled (`claude -p --tools ""`) or in a read-only sandbox in a temporary folder (`codex exec --sandbox read-only --ephemeral`), and prompts go in on stdin. Every AI call has a timeout; when it runs out or errors, the default line (or the top chat message, for a variable) is used, so a slow backend never stalls a playthrough. Measured here: Codex about 7–14 s per call.
